# ADR-0001：设计文档冲突时的裁决优先级

- 状态：已接受
- 日期：2026-09-22

## 背景

ChemAI 的设计资料分两层，且互相存在矛盾定义：

- **设计文档（Part 4）**：`产品设计/` 下的 20–43 号文档 + `系统架构图.md`
- **总体开发方案（Part 5）**：`00-总体开发方案.md`，是 18 份施工教程（44–61 号）的元方案

已核实的冲突实例：

| 冲突点 | A 说法 | B 说法 |
| --- | --- | --- |
| `QuestionSet` 中文名 | 34 号 ER 图：真题集 | 25 号 §5.2：题库文件夹 |
| 评测分层 | 00 号 §3.2：L1 单元 / L2 集成 / L3 质量 | 32 号 §1.3：基线层 / 边界层 / 回归层 |
| Golden 数据集规模 | 00 号 §1.2：100 条 | 32 号：109 个评测场景 |
| 用户角色数 | 23 号目录与概述：五角色 | 23 号正文与表格：六角色 |

## 决策

1. **同一文档内部矛盾**时，以正文为准，目录与概述段落为次。实例：23 号的角色数以正文「六角色体系」表为准。

2. **跨文档冲突**时，以该概念的**主责文档**为准：

   | 概念域 | 主责文档 |
   | --- | --- |
   | 题库 / 出题 / 考试 | 25 号 |
   | 四维安全审核 | 26 号 |
   | 障碍诊断 | 27 号 |
   | 自适应练习 | 28 号 |
   | 间隔复习 | 29 号 |
   | Agent 对话 | 30 号 |
   | 学情分析 | 31 号 |
   | 评测体系 | 32 号 |
   | 家长端 / 通知 | 33 号 |
   | 数据模型字段 | 34 号 |
   | API 约定 | 35 号 |
   | 设计系统 / 页面规格 / 样式组织 | 36 号、40 号 |
   | 桌面打包 / 前端资源清单 | 37 号 |
   | 技术选型 | 38 号 |
   | 权限与角色 | 23 号 |
   | 前端 SSE 渲染 | 41 号 |
   | 知识图谱 / 课标维度 | 42 号 |

3. **设计文档与 00 号冲突**时按性质分工裁决：

   - **功能、质量、数据的实质定义** → 以设计文档为准
   - **流程编排、工具链、Git 规范** → 以 00 号为准

4. 每次裁决必须**在一个地方留痕**：写入本 ADR、新开 ADR，或记入 `CONTEXT.md`。禁止只在对话里裁决。

5. 裁决结果**不回写上游文档**。设计文档与教程是外部资料，本仓库只记录自己的取舍。

## 影响

- 首个应用实例：`QuestionSet` 取 25 号的「题库文件夹」，34 号 ER 图的「真题集」视为笔误。详见 `CONTEXT.md` 内容实体一节。
- 第二个应用实例：评测分层口径见 [ADR-0002](0002-评测分层以设计文档为准.md)。
- 第三个应用实例：前端样式组织取 36 号（Tailwind CDN 内联），37 号的 `common.css` / `design-system.css` 处于下位。见 [ADR-0005](0005-前端样式一律走-Tailwind-CDN.md)。
- 冲突是**已知且被接受的现状**，不是待修 bug。不要因为「文档说 A、代码写了 B」就自动认为代码错了——先查本 ADR 的裁决。
