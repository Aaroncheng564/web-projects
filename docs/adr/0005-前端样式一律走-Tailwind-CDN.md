# ADR-0005：前端样式一律走 Tailwind CDN 内联

- 状态：已接受
- 日期：2026-09-22

## 背景

前端样式有两份文档给出互不相容的指示：

**36 号《设计系统》（样式主责文档）**

> 核心原则：**零构建步骤**——所有样式通过 CDN 加载的 Tailwind CSS 类名直接在 HTML 中表达，不需要编译 CSS 文件，不引入前端框架的构建复杂度。（36 号 §核心原则）

**37 号《桌面应用与打包设计》** 列出了两个独立 CSS 文件：

> 前端目录结构：`index.html` … `app.js` 共用业务逻辑、**`common.css` 共用组件样式**、**`design-system.css` 共用设计系统**、`js/` 目录 …（37 号）

`DESIGN.md`（设计权威，自述「本文件与源文档冲突时，以本文件的已知缺口章节标注的裁决为准」）的 **R7 技术栈硬约束第 17 条**：

> 样式只能用 Tailwind CDN 工具类写在 HTML 里，禁止引入需要编译的 CSS 文件。

但 `DESIGN.md` 的已知缺口 G1–G9 **没有覆盖这条 CSS 冲突**，即设计权威本身没有给出裁决。

按 [ADR-0001](0001-设计文档冲突的裁决优先级.md) 第 2 条，样式的主责文档是 36 号与 40 号，37 号的 CSS 清单处于下位。

另需注意：37 号列出的两个 CSS 文件位于**前端根目录**（与 `index.html` 同级），在任何文档中都**不存在** `css/` 子目录的概念。

**前端目录布局的完整对照**（37 号）。建这套骨架时 `frontend/m/` 一度被怀疑是笔误，核对后确认**有据可依**——记在这里，防止后来者（或 AI）把它当拼写错误清理掉：

| 位置 | 内容 | 谁加载 |
| --- | --- | --- |
| 根 `index.html` | 教师端首页 | 教师端加载 `/` |
| 根 `login.html` | 共用登录 | — |
| 根 `app.js` | 共用业务逻辑 | — |
| `js/` | 共用 JS 模块（化学式渲染等） | — |
| `pages/` | 教师端子页面 | — |
| `m/` | **学生端 / 家长端移动页面**（`index.html` / `parent-login.html` / `parent.html`） | 学生端加载 `/m/index.html`；家长端加载 `/m/parent-login.html` |
| `css/` | **无文档依据**——见上文决策 4、5 | — |

`m` 是 **mobile** 的缩写。全目录词频核对：`m/` 出现 8 次、`pages/` 出现 5 次、`css/` 出现 **0** 次。除 `css/` 外，前端骨架与文档逐项吻合。

## 决策

1. **样式一律用 Tailwind CDN 的工具类内联写在 HTML 中**，零构建步骤。
2. **不创建 `common.css` 与 `design-system.css`**。37 号的那份目录清单在样式部分被本 ADR 取代。
3. **禁止引入需要编译的 CSS**：不写 Tailwind 的 `@tailwind` 指令，不配 PostCSS，`vite` 不承担 CSS 构建职责（它只做 dev server、HMR、API proxy）。
4. **`frontend/css/` 目录目前没有文档依据的用途。** 保留它是因为它已在初始骨架中，但只允许放**手写的、无需构建步骤的补丁样式**（典型场景：KaTeX / mhchem 渲染细节、打印样式、滚动条）。**不得**在其中放 Tailwind 源文件或任何进入构建管线的输入。
5. **清理触发点**：到阶段三（前端页面开工）结束时，若 `frontend/css/` 仍为空或无明确用途，删除该目录并回填本 ADR。

## 影响

- `CLAUDE.md` 的「项目特定规范」增加一条样式硬约束。
- 生成任何页面前必须先读 `DESIGN.md`——它才是设计参数的权威来源，本 ADR 只裁决 CSS 的组织方式。
- 若将来确实需要编译型 CSS（例如引入 PostCSS 插件），那是对 R7 的推翻，需先取代本 ADR 与 `DESIGN.md` 的 R7。
